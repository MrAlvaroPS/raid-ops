# Current architecture baseline

## Product boundary

AvoiD Raid Ops is an operational raid-intelligence system. It combines official encounter semantics, observed combat, AvoiD execution history and derived Iris diagnosis while preserving the evidence class and empirical scope of every conclusion.

The migration must preserve these planes:

| Plane | Authority | Permitted product role |
|---|---|---|
| Official | Blizzard Encounter Journal | Published raid/boss hierarchy and build-specific membership. |
| Structural | Build-pinned Wago DB2 | Bounded structural relations; never observed causality. |
| Observed GLOBAL | Warcraft Logs | Combat truth scoped by encounter, difficulty and partition. |
| Observed HOME | AvoiD reports | Application/evaluation and raid execution; never GLOBAL training or holdout. |
| Inferred | Iris | AvoiD-specific diagnosis with explicit provenance and evidence gates. |
| Loot | Blizzard, WCL, SimulationCraft, local ledger | Item applicability and independent award signals; never automatic award authority. |

## Runtime topology

```text
index.html
  ├─ compiled Golden React bundle (main.js)
  ├─ 21 directly loaded additive JavaScript runtimes
  ├─ 2 more dynamically loaded Loot runtimes
  └─ 28 cumulative CSS files
           ↓ DOM replacement, timers, browser events, window.__AVOID_* globals
Nitro routes/api (32 routes)
           ↓
services + engines + corpus + knowledge + loot
           ↓
WCL / Blizzard / Wago DB2 / SimulationCraft
           ↓
Vercel Blob or local JSON corpus
```

The reconstructed React source in `apps/web` is not the production source of truth. It is versioned independently, still imports Golden mocks and omits current runtime integrations.

## Ownership problems to preserve as defects, not features

1. The Golden bundle initially owns every section and contains fictional metrics and actors.
2. Later runtimes selectively replace or patch those screens.
3. A section can therefore display a real empty-state banner alongside surviving fictional Golden content.
4. Navigation state, breadcrumb state and rendered page ownership can disagree.
5. Timers and observers infer the active page from the DOM instead of a router.
6. Script load order is part of application behaviour but is not expressed as a dependency graph.
7. Configuration and release identifiers are duplicated in the server, browser, HTML, tests and documentation.

Observed examples in the offline baseline:

- Players reports zero real profiles while the fictional Golden roster remains visible.
- Loot renders its current surface while Composition remains in the breadcrumb and both navigation entries appear active.
- Data & Logs is not reachable in a fresh offline profile because its button is not mounted after selector ownership changes.
- The mobile top execution controls overflow the viewport.
- Command Center, Damage & Healing and Defensive Audit retain Golden values when real data is unavailable.

## Backend baseline

The backend already contains valuable boundaries and must initially remain in service behind Angular. The first frontend migration does not rewrite Nitro, WCL acquisition, Iris evidence logic or persistence.

Debt to address during and after parity work:

- large orchestration routes that bypass thin route handlers;
- duplicated acquisition/normalisation between intelligence and operational execution engines;
- configuration defaults repeated in browser and server;
- inactive or aspirational domain/repository/ingestion packages;
- legacy and current service generations coexisting;
- explicit-difficulty contract violations caused by silent `difficulty || 5` defaults.

## Angular target baseline

The sibling `raid-ops` repository is an Angular 21.2 scaffold. It has nine source files, no product feature, no API integration and no migrated state. This is desirable for the incremental plan: Angular can consume the existing backend through an anti-corruption API layer without carrying over the current DOM patching model.

## Baseline limitations

- Offline screenshots intentionally prove zero provider acquisition, so they do not represent connected or live telemetry.
- Browser Cache Storage is derived and profile-specific; it is not migration authority.
- No repository-managed PostgreSQL/database runtime was found. A separately managed local database remains an external item to confirm.
- Historical tests include both real regressions and stale exact-asset expectations. Phase 1 owns their classification and stabilisation.
